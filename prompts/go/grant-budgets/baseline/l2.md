```yaml
openapi: 3.0.3
info:
  title: Minimal Grant Budget API
  version: 1.0.0
servers:
  - url: http://localhost:{port}/api
    variables:
      port:
        default: "3137"
paths:
  /health-check:
    get:
      responses:
        "200": { description: Server is healthy. }
  /users:
    post:
      requestBody:
        required: true
        content:
          application/json:
            schema:
              type: object
              properties:
                username: { type: string, minLength: 1 }
              required: [username]
      responses:
        "201": { description: User created. }
        "400": { description: Invalid request. }
        "409": { description: Duplicate username. }
  /grants:
    post:
      requestBody:
        required: true
        content:
          application/json:
            schema:
              type: object
              properties:
                code: { type: string, minLength: 1 }
                awardCents: { type: integer, minimum: 1 }
                budgetCents: { type: integer, minimum: 1 }
                perUserLimit: { type: integer, minimum: 1 }
              required: [code, awardCents, budgetCents, perUserLimit]
      responses:
        "201": { description: Grant created. }
        "400": { description: Invalid request. }
        "409": { description: Duplicate code. }
  /claims:
    post:
      security:
        - Token: []
      requestBody:
        required: true
        content:
          application/json:
            schema:
              type: object
              properties:
                externalId: { type: string, minLength: 1 }
                grantCode: { type: string, minLength: 1 }
              required: [externalId, grantCode]
      responses:
        "201": { description: Claim created. }
        "200": { description: Existing idempotent claim returned. }
        "400": { description: Invalid request. }
        "401": { description: Missing or invalid token. }
        "404": { description: Grant missing. }
        "409": { description: Budget exceeded or per-user limit exceeded. }
  /claims/{claimId}/void:
    post:
      security:
        - Token: []
      parameters:
        - name: claimId
          in: path
          required: true
          schema:
            type: string
      responses:
        "200": { description: Claim voided. }
        "401": { description: Missing or invalid token. }
        "403": { description: Claim belongs to another user. }
        "404": { description: Claim missing. }
        "409": { description: Claim already voided. }
  /grants/{grantId}/summary:
    get:
      parameters:
        - name: grantId
          in: path
          required: true
          schema:
            type: string
      responses:
        "200": { description: Grant summary. }
        "404": { description: Grant missing. }
components:
  securitySchemes:
    Token:
      type: apiKey
      in: header
      name: Authorization
```

Generate a complete Go REST API server compliant with the OpenAPI
specification above.

## Requirements

- Use Go 1.22 or newer.
- Use the standard library `net/http` package and `http.ServeMux` for routing.
- Do not use Gin, chi, Echo, Fiber, Gorilla mux, or other HTTP frameworks.
- Work only in the current directory.
- Create a `go.mod` file and a runnable `main.go`.
- `go.mod` must declare a module name and a `go` directive. It is acceptable
  for `go.mod` to contain only those lines when third-party packages are used;
  the evaluator runs `go mod tidy` to resolve imports.
- Use normal Go module dependencies. Do not vendor dependencies and do not
  hand-pin guessed or fictional module versions.
- The evaluator will run `go run .`; that command must start the HTTP server
  without additional arguments.
- The server must listen on `os.Getenv("PORT")`, defaulting to `3137` when
  the environment variable is unset.
- All API routes must be prefixed with `/api`.
- `GET /api/health-check` must return HTTP 200.
- Use JSON request and response bodies unless a task-specific rule says
  otherwise.
- Define named request, response, and domain structs and reuse those types across
  helpers. Do not pass anonymous struct types across function boundaries.
- Keep numeric money/count fields on one integer type throughout a calculation.
- Remove unused imports and undefined identifiers before finishing.
- Before finishing, run `go mod tidy` and `go build ./...`; fix any failures.
- Implement all behavior from the OpenAPI specification.

## Structural Constraints

- Follow a layered architecture.
- Keep routes, services, repositories, and models in separate directories or
  packages.
- Routes may call services.
- Services may call repositories and models.
- Repositories may call models.
- Lower layers must not import higher layers.
- Persist all task entities and mutable state in SQLite using `database/sql`
  with the pure-Go `modernc.org/sqlite` driver.
- Import `modernc.org/sqlite` for its database/sql driver side effect and let
  `go mod tidy` resolve the module version.
- Create the SQLite schema automatically on server startup.
- Do not use in-memory-only storage for persisted entities.

## Task-Specific Behavior

Implement grant budgets and authenticated claims.

Authentication uses `Authorization: Token <token>`.

Response shapes:

- User: `{ "id", "username", "token", "createdAt" }`
- Grant: `{ "id", "code", "awardCents", "budgetCents", "perUserLimit", "createdAt" }`
- Claim: `{ "id", "userId", "externalId", "grantId", "grantCode", "awardCents", "status", "createdAt" }`
- Summary: `{ "grantId", "activeClaimCount", "voidedClaimCount", "awardedCents", "remainingBudgetCents", "activeClaimIds" }`

Rules:

- Grant codes are unique.
- Claims look up the grant by `grantCode`.
- `externalId` is idempotent per authenticated user. Repeating the same
  `externalId` returns HTTP `200` with the original claim and does not spend
  more budget.
- A user can have at most `perUserLimit` active claims for a grant.
- Active claims consume grant budget. Voided claims do not consume budget.
- Voiding a claim releases its award back to the grant budget and no longer
  counts against the user's limit.
- Voiding another user's claim returns `403`.
- Voiding an already voided claim returns `409`.
- If budget or per-user limit would be exceeded, return `409` and do not create
  or mutate a claim.

## Evaluation

The evaluator will:

1. Run `go mod tidy`.
2. Run `go mod download`.
3. Run `go build ./...`.
4. Run `go run .`.
5. Poll `GET /api/health-check`.
6. Execute black-box HTTP tests against the API.

Finish only after the implementation is ready to run with those commands.
