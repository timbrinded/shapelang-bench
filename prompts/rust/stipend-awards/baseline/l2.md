```yaml
openapi: 3.0.3
info:
  title: Minimal Stipend Award API
  version: 1.0.0
servers:
  - url: http://localhost:{port}/api
    variables:
      port:
        default: "3137"
paths:
  /health-check:
    get:
      responses:
        "200": { description: Server is healthy. }
  /users:
    post:
      requestBody:
        required: true
        content:
          application/json:
            schema:
              type: object
              properties:
                username: { type: string, minLength: 1 }
              required: [username]
      responses:
        "201": { description: User created. }
        "400": { description: Invalid request. }
        "409": { description: Duplicate username. }
  /stipends:
    post:
      requestBody:
        required: true
        content:
          application/json:
            schema:
              type: object
              properties:
                code: { type: string, minLength: 1 }
                awardCents: { type: integer, minimum: 1 }
                budgetCents: { type: integer, minimum: 1 }
                perUserLimit: { type: integer, minimum: 1 }
              required: [code, awardCents, budgetCents, perUserLimit]
      responses:
        "201": { description: Stipend created. }
        "400": { description: Invalid request. }
        "409": { description: Duplicate code. }
  /awards:
    post:
      security:
        - Token: []
      requestBody:
        required: true
        content:
          application/json:
            schema:
              type: object
              properties:
                externalId: { type: string, minLength: 1 }
                stipendCode: { type: string, minLength: 1 }
              required: [externalId, stipendCode]
      responses:
        "201": { description: Award created. }
        "200": { description: Existing idempotent award returned. }
        "400": { description: Invalid request. }
        "401": { description: Missing or invalid token. }
        "404": { description: Stipend missing. }
        "409": { description: Budget exceeded or per-user limit exceeded. }
  /awards/{awardId}/rescind:
    post:
      security:
        - Token: []
      parameters:
        - name: awardId
          in: path
          required: true
          schema:
            type: string
      responses:
        "200": { description: Award rescinded. }
        "401": { description: Missing or invalid token. }
        "403": { description: Award belongs to another user. }
        "404": { description: Award missing. }
        "409": { description: Award already rescinded. }
  /stipends/{stipendId}/summary:
    get:
      parameters:
        - name: stipendId
          in: path
          required: true
          schema:
            type: string
      responses:
        "200": { description: Stipend summary. }
        "404": { description: Stipend missing. }
components:
  securitySchemes:
    Token:
      type: apiKey
      in: header
      name: Authorization
```

## Requirements

- Use stable Rust with Cargo edition 2021.
- Do not create a `rust-toolchain` file and do not require nightly Rust.
- Use axum 0.8 for HTTP routing and Tokio 1 for the async runtime.
- Work only in the current directory.
- Create a `Cargo.toml` file and a runnable `src/main.rs`.
- `Cargo.toml` must include a `[package]` table, `edition = "2021"`, and
  normal crates.io dependencies. Do not vendor dependencies.
- Use one coherent axum version across the project. Avoid mixing examples from
  axum 0.6, 0.7, and 0.8.
- The evaluator will run `cargo run --quiet`; that command must start the HTTP
  server without additional arguments.
- The server must listen on `std::env::var("PORT")`, defaulting to `3137`
  when the environment variable is unset.
- All API routes must be prefixed with `/api`.
- `GET /api/health-check` must return HTTP 200.
- Use JSON request and response bodies unless a task-specific rule says
  otherwise.
- Every `mod foo;` declaration must have a matching `src/foo.rs` or
  `src/foo/mod.rs` file, and every sibling module import should use
  `crate::...` paths.
- Handler return types must be type-consistent. Prefer returning
  `axum::response::Response` and ending every branch with
  `.into_response()` when branches return different JSON/error shapes.
- Avoid holding overlapping mutable borrows across later mutations; clone IDs or
  split operations into separate scopes before mutating the same state again.
- Before finishing, run `cargo build --quiet`; fix any failures.
- Implement all behavior from the OpenAPI specification.

## Structural Constraints

- Follow a layered architecture.
- Keep routes, services, repositories, and models in separate directories or
  packages.
- Routes may call services.
- Services may call repositories and models.
- Repositories may call models.
- Lower layers must not import higher layers.
- Persist all task entities and mutable state in SQLite using SQLx with the
  `sqlite` and Tokio runtime features enabled.
- Declare SQLx as
  `sqlx = { version = "0.8", features = ["runtime-tokio-rustls", "sqlite"] }`.
- Create the SQLite schema automatically on server startup.
- Do not use in-memory-only storage for persisted entities.

## Task-Specific Behavior

Implement stipend budgets and authenticated awards.

Authentication uses `Authorization: Token <token>`.

Response shapes:

- User: `{ "id", "username", "token", "createdAt" }`
- Stipend: `{ "id", "code", "awardCents", "budgetCents", "perUserLimit", "createdAt" }`
- Award: `{ "id", "userId", "externalId", "stipendId", "stipendCode", "awardCents", "status", "createdAt" }`
- Summary: `{ "stipendId", "activeAwardCount", "rescindedAwardCount", "awardedCents", "remainingBudgetCents", "activeAwardIds" }`

Rules:

- Stipend codes are unique.
- Awards look up the stipend by `stipendCode`.
- `externalId` is idempotent per authenticated user. Repeating the same
  `externalId` returns HTTP `200` with the original award and does not spend
  more budget.
- A user can have at most `perUserLimit` active awards for a stipend.
- Active awards consume stipend budget. Rescinded awards do not consume budget.
- Rescinding an award changes its `status` to exactly `rescinded`.
- Rescinding an award releases its amount back to the stipend budget and no
  longer counts against the user's limit.
- Rescinding another user's award returns `403`.
- Rescinding an already rescinded award returns `409`.
- If budget or per-user limit would be exceeded, return `409` and do not create
  or mutate an award.
