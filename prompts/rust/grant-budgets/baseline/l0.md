```yaml
openapi: 3.0.3
info:
  title: Minimal Grant Budget API
  version: 1.0.0
servers:
  - url: http://localhost:{port}/api
    variables:
      port:
        default: "3137"
paths:
  /health-check:
    get:
      responses:
        "200": { description: Server is healthy. }
  /users:
    post:
      requestBody:
        required: true
        content:
          application/json:
            schema:
              type: object
              properties:
                username: { type: string, minLength: 1 }
              required: [username]
      responses:
        "201": { description: User created. }
        "400": { description: Invalid request. }
        "409": { description: Duplicate username. }
  /grants:
    post:
      requestBody:
        required: true
        content:
          application/json:
            schema:
              type: object
              properties:
                code: { type: string, minLength: 1 }
                awardCents: { type: integer, minimum: 1 }
                budgetCents: { type: integer, minimum: 1 }
                perUserLimit: { type: integer, minimum: 1 }
              required: [code, awardCents, budgetCents, perUserLimit]
      responses:
        "201": { description: Grant created. }
        "400": { description: Invalid request. }
        "409": { description: Duplicate code. }
  /claims:
    post:
      security:
        - Token: []
      requestBody:
        required: true
        content:
          application/json:
            schema:
              type: object
              properties:
                externalId: { type: string, minLength: 1 }
                grantCode: { type: string, minLength: 1 }
              required: [externalId, grantCode]
      responses:
        "201": { description: Claim created. }
        "200": { description: Existing idempotent claim returned. }
        "400": { description: Invalid request. }
        "401": { description: Missing or invalid token. }
        "404": { description: Grant missing. }
        "409": { description: Budget exceeded or per-user limit exceeded. }
  /claims/{claimId}/void:
    post:
      security:
        - Token: []
      parameters:
        - name: claimId
          in: path
          required: true
          schema:
            type: string
      responses:
        "200": { description: Claim voided. }
        "401": { description: Missing or invalid token. }
        "403": { description: Claim belongs to another user. }
        "404": { description: Claim missing. }
        "409": { description: Claim already voided. }
  /grants/{grantId}/summary:
    get:
      parameters:
        - name: grantId
          in: path
          required: true
          schema:
            type: string
      responses:
        "200": { description: Grant summary. }
        "404": { description: Grant missing. }
components:
  securitySchemes:
    Token:
      type: apiKey
      in: header
      name: Authorization
```

Generate a complete Rust REST API server compliant with the OpenAPI
specification above.

## Requirements

- Use stable Rust.
- Use axum for HTTP routing and Tokio for the async runtime.
- Work only in the current directory.
- Create a `Cargo.toml` file and a runnable `src/main.rs`.
- Use normal crates.io dependencies. Do not vendor dependencies.
- The evaluator will run `cargo run --quiet`; that command must start the HTTP
  server without additional arguments.
- The server must listen on `std::env::var("PORT")`, defaulting to `3137`
  when the environment variable is unset.
- All API routes must be prefixed with `/api`.
- `GET /api/health-check` must return HTTP 200.
- Use JSON request and response bodies unless a task-specific rule says
  otherwise.
- Implement all behavior from the OpenAPI specification.

## Structural Constraints

- No additional structural constraints.
- In-memory storage is allowed.

## Task-Specific Behavior

Implement grant budgets and authenticated claims.

Authentication uses `Authorization: Token <token>`.

Response shapes:

- User: `{ "id", "username", "token", "createdAt" }`
- Grant: `{ "id", "code", "awardCents", "budgetCents", "perUserLimit", "createdAt" }`
- Claim: `{ "id", "userId", "externalId", "grantId", "grantCode", "awardCents", "status", "createdAt" }`
- Summary: `{ "grantId", "activeClaimCount", "voidedClaimCount", "awardedCents", "remainingBudgetCents", "activeClaimIds" }`

Rules:

- Grant codes are unique.
- Claims look up the grant by `grantCode`.
- `externalId` is idempotent per authenticated user. Repeating the same
  `externalId` returns HTTP `200` with the original claim and does not spend
  more budget.
- A user can have at most `perUserLimit` active claims for a grant.
- Active claims consume grant budget. Voided claims do not consume budget.
- Voiding a claim releases its award back to the grant budget and no longer
  counts against the user's limit.
- Voiding another user's claim returns `403`.
- Voiding an already voided claim returns `409`.
- If budget or per-user limit would be exceeded, return `409` and do not create
  or mutate a claim.
